<objective>
Bind `ticket_id` to the run's actual ticket server-side, reject any model-supplied mismatch with a recoverable, model-readable denial, and make that denial observable as a new `guardrail` SSE event (SEC-04, D-09/D-10/D-11).

Purpose: this is the indirect-prompt-injection control. A ticket body is untrusted input that reaches the model, and the model's tool arguments are therefore untrusted output. The single choke point every tool call passes through is `_execute_guarded`, so that is where server truth must be asserted. The observable rejection is also the phase's demo artifact and the hook Phase 4's EVAL-02 asserts on.
Output: a keyword-only `bound_ticket_id` guard in the chain, a `guardrail` event emitted before the corresponding `tool_result`, and four new tests.

This plan is deliberately independent of the auth/rate-limit work — it shares no files with plan 01 and runs in the same wave.
</objective>

Guard-chain signature after this plan (return arity MUST stay `tuple[str, bool]` —
`mcp_server.call_mcp_tool` unpacks exactly two values):

```
def _execute_guarded(
    spec: ToolSpec | None,
    name: str,
    raw_input: dict[str, Any],
    policy: ToolPolicy,
    *,
    bound_ticket_id: int | None = None,
) -> tuple[str, bool]
```

Denial payload returned on mismatch (JSON-encoded, `is_error=True`), mirroring the
existing `{"error": ..., "denied_by": "policy"}` precedent:

```
{
  "error": "<recoverable instruction naming the correct ticket id>",
  "denied_by": "ticket_binding",
  "expected_ticket_id": <int>,
  "supplied_ticket_id": <int>
}
```

New SSE event (additive; `guard` is a discriminator so future guard types reuse the type):

```
AgentEvent(type="guardrail", data={
  "guard": "ticket_binding",
  "tool": <str>,
  "expected_ticket_id": <int>,
  "supplied_ticket_id": <int>,
  "action": "denied",
})
```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Ticket body → model prompt | Ticket `subject`/`body` are attacker-controlled text that reaches the Claude prompt verbatim (indirect prompt injection surface) |
| Model output → tool executor | `tool_use.input` is untrusted output derived from untrusted input; it must never be treated as authority over which record is mutated |
| Concurrent runs → shared registry | One `build_registry` result is shared by every in-flight run in the process |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-05 | Tampering / Elevation of Privilege | `_execute_guarded` → `send_reply` / `create_escalation` / `set_category` | mitigate | Compare validated `ticket_id` against the run-bound `bound_ticket_id` between validation and execution; reject with `denied_by="ticket_binding"` (D-09). Proven by `test_mismatched_ticket_id_is_denied` |
| T-01-06 | Tampering | Per-run state stored on the shared `app.state.registry` | mitigate | Bind at call time from the run's own `ticket` dict; never mutate the registry. Proven by `test_concurrent_runs_do_not_cross_bind` |
| T-01-07 | Repudiation | An injection attempt that leaves no trace | mitigate | `guardrail` SSE event + `logger.warning("guardrail.ticket_id_mismatch", ...)` + OTel span attribute `relay.tool.binding_violation`. Feeds Phase 4 EVAL-02 and Phase 5 run_events |
| T-01-08 | Denial of Service | A denial that terminates the run, converting an injection into an availability failure and an eval regression | mitigate | Denial is returned as a model-readable recoverable instruction naming the correct id; the loop continues under existing step/budget limits (D-10). Proven by `test_run_recovers_after_binding_denial` |
| T-01-09 | Information Disclosure | Ticket bodies leaking into structured logs via the denial path | mitigate | `ctx` carries only `ticket_id`, `tool`, `supplied_ticket_id` — never the body, never key material; `JsonFormatter` flattens `ctx` to stdout |
| T-01-10 | Tampering | Changing `_execute_guarded` return arity breaks the MCP guard path silently | accept (guarded) | Arity fixed at `tuple[str, bool]`; enforced by an acceptance criterion and by the six existing MCP tests |

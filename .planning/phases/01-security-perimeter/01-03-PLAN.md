<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Internet → FastAPI request | Every header, including `X-API-Key` and `Fly-Client-IP`, is attacker-controlled until proven otherwise |
| Fly proxy → app | The TCP peer is the proxy; the real client IP exists only as a proxy-injected header |
| App → structured logs (stdout) | `JsonFormatter` flattens the whole `ctx` dict; anything placed there ships to the log sink |
| App → `runs` table | The observability table becomes a control input for the spend ceiling |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-11 | Information Disclosure | Key comparison timing in `resolve_tier` | mitigate | `secrets.compare_digest` on bytes; both tier comparisons evaluated unconditionally before branching. Grep-asserted: no `elif` short-circuit between comparisons |
| T-01-12 | Denial of Service (500) | Non-ASCII `X-API-Key` raising `TypeError` on `str` comparison | mitigate | `.encode()` both sides before `compare_digest`; unit test asserts a clean `None` rather than a raise |
| T-01-13 | Elevation of Privilege | Fail-open when `RELAY_API_KEY` is unset on deploy | mitigate | `require_tier` raises 503 when no key is configured, per request (never at startup, so `/health` and container boot are unaffected) |
| T-01-14 | Spoofing | Forged `Fly-Client-IP` minting unlimited rate-limit buckets | mitigate | Header honored only when `settings.trust_proxy_header` is true (default false); `RELAY_TRUST_PROXY='true'` is set only in `fly.toml` where the proxy actually overwrites it (plan 04) |
| T-01-15 | Denial of Service | Cost amplification — each request drives up to 10 Claude calls | mitigate | Per-tier moving window (`enforce`) bounds burst; SQLite-derived daily ceiling (`enforce_daily_budget`) bounds aggregate and survives cold starts on a scale-to-zero machine |
| T-01-16 | Denial of Service | Concurrent runs invisible to the ceiling because `record_run` fires only after the stream ends | mitigate | `reserve_run` / `release_run` add `max_run_cost_usd` per admitted run to the effective spend |
| T-01-17 | Denial of Service | Rate-limit bypass via IP rotation or cold-start bucket reset | accept | Per-IP limits cannot stop rotation by design, and in-memory buckets are intentionally ephemeral. The persistent daily spend ceiling is the actual control — which is exactly why SEC-03 exists separately from SEC-02 |
| T-01-18 | Information Disclosure | Credential leakage via logs | mitigate | `auth.rejected` / `ratelimit.exceeded` log the resolved tier and IP only; presented and configured keys are never placed in `ctx`. Grep-asserted |
| T-01-19 | Tampering | SQL injection in the new daily-spend query | mitigate | The query is a static constant with zero parameters and zero user input; all other queries remain `?`-parameterized |

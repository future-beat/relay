<objective>
Compose auth, the daily spend ceiling and the rate limiter into a single ordered gate and apply it to the three protected routes — while leaving `/`, `/health`, `/metrics` and `/dashboard` public — then prove the whole perimeter with integration tests.

Purpose: placement is the entire risk here. Every control must resolve as a FastAPI route dependency, BEFORE the handler returns `StreamingResponse`. The moment the SSE generator yields its first byte the status line is locked at 200, and a 401/429/503 becomes impossible to express — a rejection rendered as an in-stream `event: error` is not a rate limit. `BaseHTTPMiddleware` is forbidden for the same reason plus its documented interference with `request.is_disconnected()` on streaming responses.
Output: a `run_gate` composition, three gated routes, the in-flight reservation seam, `RELAY_TRUST_PROXY` in `fly.toml`, and the integration half of `test_auth.py` / `test_ratelimit.py`.
</objective>

Route → bucket → gate mapping produced by this plan (D-07):

| Route | Public? | Bucket | Gate |
|-------|---------|--------|------|
| `GET /` | yes | — | none |
| `GET /health` | yes | — | none |
| `GET /metrics` | yes | — | none |
| `GET /dashboard` | yes | — | none |
| `POST /tickets` | no | `create` | auth → rate limit |
| `GET /tickets/{id}` | no | `read` | auth → rate limit |
| `POST /tickets/{id}/process` | no | `process` | auth → daily budget → rate limit |

Gate ordering inside the process gate: auth resolves first (FastAPI resolves sub-dependencies
before the dependant), then the daily budget (a *global* condition — checking it first avoids
burning a caller's per-IP token during a budget outage), then the per-IP rate limit.

Verified FastAPI 0.141.1 semantics relied on here:
- route `dependencies=[Depends(a), Depends(b)]` execute in declaration order and short-circuit on the first raise
- `HTTPException(401, ..., headers={"WWW-Authenticate": "APIKey"})` reaches the wire with the header intact
- a dict `HTTPException.detail` serializes as `{"detail": {...}}` with custom headers preserved

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Internet → route handler | The first place server policy can still be expressed as an HTTP status; after the SSE generator yields, it cannot |
| Fly proxy → app | `Fly-Client-IP` is authoritative only here, which is why `RELAY_TRUST_PROXY` ships in `fly.toml` and nowhere else |
| Deploy pipeline → live service | Fly secrets must exist before the fail-closed deploy lands, or the live demo 503s |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-20 | Elevation of Privilege | Unauthenticated `POST /tickets`, `POST /tickets/{id}/process`, `GET /tickets/{id}` | mitigate | `Depends(require_tier("owner","demo"))` resolved before the handler builds a response; proven by the 401 route tests |
| T-01-21 | Denial of Service | Controls placed where they cannot take effect (middleware, or inside `event_stream`) | mitigate | Route dependencies only; grep-asserted absence of `app.middleware`/`BaseHTTPMiddleware`; ordering verified against FastAPI's declaration-order short-circuit |
| T-01-22 | Denial of Service | Global auth accidentally covering `/health` and killing the container HEALTHCHECK and CI smoke job | mitigate | Allowlist of protected routes rather than a denylist of exempt paths; `test_public_routes_need_no_key` plus a docker smoke acceptance criterion |
| T-01-23 | Denial of Service | Cost amplification through the process endpoint | mitigate | Ordered gate: budget (global) before rate limit (per-IP) so a budget outage does not consume a caller's allowance; both precede any model call |
| T-01-24 | Spoofing | `Fly-Client-IP` trusted off-proxy | mitigate | `RELAY_TRUST_PROXY = 'true'` set only in `fly.toml [env]`; default remains false everywhere else |
| T-01-25 | Denial of Service | Reservation leak — `reserve_run` without a matching `release_run` permanently exhausting the ceiling | mitigate | Release lives in a `finally` inside `event_stream` after `record_run`, so it runs on completion, error, and client abandonment. Never an `async with` (would corrupt the span tree across yields) |
| T-01-26 | Information Disclosure | Demo-key holders enumerating ticket bodies and `customer_email` via `GET /tickets/{id}` | accept | Zero-tenant demo seeded with fictional customers; per-tier ticket ownership needs a new `tickets` column and is Phase 5/6 territory. A loose `read` limit blunts scraping; the exposure is documented in the README threat-model paragraph in plan 05 |
| T-01-27 | Elevation of Privilege | Deploy without `fly secrets set RELAY_API_KEY` | mitigate | Fail-closed 503 makes the omission loud rather than silently open; the required ops step is documented in plan 05's README deploy notes |
</threat_model>

<objective>
Make `/metrics` the data API the dashboard reads: outcome distribution and totals computed by SQL aggregation (DASH-02), a dense daily cost/latency series over a bounded window (DASH-04 / D-10), one definition of "median" shared by the card and the chart, and `run_uid` restored to `last_runs` so a run in the table has a handle to drill into.

Purpose: today `run_metrics` materialises every row of `runs` and aggregates in Python on a route that is ungated and polled every 5 s per tab — the one read `main.py:412` already flags as growing unbounded. DASH-02 names SQL aggregation, and the charts need per-day buckets that a full materialisation cannot cheaply produce. The `run_uid` restoration is the orchestrator's explicit reversal of WR-10: the drill-down this key opens is server-redacted (D-01/D-03), so the disclosure WR-10 guarded against no longer exists.

Output: rewritten `run_metrics` in `telemetry.py`; new `tests/test_metrics.py`; the WR-10 test in `tests/test_run_events.py` restated to its new, coherent position.
</objective>

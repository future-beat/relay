<objective>
Build the drill-down redactor: `project_run_detail`, beside `project()` in `events.py`, turning one run's stored `run_events` rows into DASH-03's step list — tool names and argument KEYS, retrieval doc ids with scores and cited-vs-not, guardrail denials as their enumerated facts, per-step timings — through a field-by-field allowlist, with a second, explicitly-named allowlist for D-02's demo exception.

Purpose: this is the phase's security boundary. The drill-down is a bigger disclosure surface than the live feed and, unlike the feed, it is a *back catalogue*: `attribute_to_run`'s docstring draws exactly that line. WR-04 requires the redaction boundary to be one file a reviewer can open, so this belongs in `events.py` and nowhere else. Reusing `_project_tool_result` for the public branch is what makes "the drill-down can never disclose more of a tool result than the feed already does" a structural property rather than a promise.

Output: `normalise_citation` in `retrieval.py` (called by both the guard and the projector), `project_run_detail` in `events.py`, two corrected docstrings, and unit coverage of the allowlist.
</objective>

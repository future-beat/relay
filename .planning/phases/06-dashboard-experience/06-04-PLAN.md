<objective>
Serve the drill-down: a public, rate-limited `GET /runs/{run_uid}` that reads one run's `run_events` rows, decides full fidelity server-side from `tickets.origin`, and returns `project_run_detail`'s output — plus the plumbing that makes it usable: the creation tier recorded on the ticket (D-02), the run uid returned to its submitter so Try-it can deep-link its own run, the anti-buffering headers both streaming routes lack, and the `budget` object on `/metrics` (D-11).

Purpose: this is where the phase's security boundary becomes reachable from the internet. The load-bearing test lives here — a non-demo run's drill-down must disclose nothing, proven by sentinels shown present in the raw rows first, and mutation-checked twice. Its inverse lives here too: a demo run's drill-down MUST return the raw payloads, or D-02's whole point silently regresses.

Output: changed `main.py` (one new route, three small plumbing edits); the leak/tampering/inverse/absence/limit suite in `tests/test_dashboard.py`.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| anonymous internet → GET /runs/{uid} | A keyless route over a table holding raw customer PII, reachable with any uid harvested from the public feed or /metrics |
| client request → full_fidelity decision | The one authorization decision this phase makes; every client-reachable input is a tampering vector |
| POST /tickets tier → tickets.origin | The creation tier is the only server-side signal that a ticket is visitor-authored |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-13 | Information disclosure | uid harvested → drill-down over the 30-day back catalogue | mitigate | `project_run_detail`'s allowlist (plan 06-03) + the load-bearing leak test here, mutation-checked twice; retention already bounds the catalogue to 30 days |
| T-06-14 | Tampering | client forces full fidelity (`?full=1`, `X-Demo`, a cookie) | mitigate | The route derives `full_fidelity` only from `tickets.origin`; no request-derived parameter exists in the signature; `test_full_fidelity_is_server_decided` sends all of them and requires a byte-identical response |

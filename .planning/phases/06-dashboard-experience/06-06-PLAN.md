<objective>
Put the drill-down on the page: a native `<dialog>` fed by `GET /runs/{run_uid}`, opened from the runs table and from the live feed, rendering one run's ordered steps with their timings, the tools it called and the argument keys it used, the retrieval chunks it saw with their scores and whether the reply actually cited them, and the guardrail denials that fired — every value written with `textContent`.

Purpose: SC-2 of the phase. This is where "observably-real" stops being a claim: a visitor clicks a run and sees the reasoning, the grounding and the guardrails, and — for a run they submitted themselves — the raw inputs and outputs. The cited-vs-not highlighting is the part that makes the grounding legible rather than merely claimed.

Output: the drill block in `templates/dashboard.html` plus its entry points, and the grep/regression tests that keep the rendering rule and Phase 5's feed intact.
</objective>

  { run_uid, ticket_id, demo (bool), status ("complete"|"in_flight"|"swept"|"unrecorded"),

    output_tokens, model, created_at, ticket_id} or null), steps: [...] }
and, on the demo branch ONLY, `ticket: {subject, body}` (never customer_email).
404 with a short-string detail for a malformed or unknown uid.

Each step (plan 06-03's `project_run_detail`) carries `seq`, `type`, `elapsed_ms`, plus per type:
  usage        -> steps, input_tokens, output_tokens, cost_usd
  text         -> char_count            (demo adds: text)
  tool_use     -> tool, arg_keys[], unknown_arg_count   (demo adds: input)
  tool_result  -> tool, is_error, denied_by | results[{doc,id,score,cited}] | reply_id/status |
                  escalation_id/status | category, plus duration_ms   (demo adds: result)
  guardrail    -> guard, tool, action, expected_ticket_id, supplied_ticket_id, missing_count
                                          (demo adds: missing_citations[])
  notice       -> kind, tool, retrieval_mode, cause, result_count
  resolution   -> via, cost_usd, steps
  error        -> reason, status, error_type
Unknown types were dropped server-side; a malformed row was dropped too, so a gap in `seq` is possible
and must not break the renderer.

steps, input_tokens, output_tokens, cost_usd, outcome, created_at. A pre-Phase-5 row has `run_uid` null —

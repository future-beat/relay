Create `src/relay/runs.py` implementing exactly the interface in the `<interfaces>` block, following RESEARCH.md § Code Examples §3.

Module docstring must do the same job `ratelimit.py`'s does: state the scope (in-flight agent-run tracking, used this phase to drain SSE streams before the database closes and next phase to render what is running right now) and state what it deliberately is *not* — it is not part of `ratelimit.py`, because that module is scoped to burst limiting and the daily spend ceiling and run-lifecycle tracking is neither.

`ActiveRun` is a `@dataclass(frozen=True)` with `ticket_id: int` and `started_at: float`. Plain annotated fields, no validation — Pydantic is reserved for wire and tool inputs.

`RunRegistry.__init__` sets `self._active: dict[int, ActiveRun] = {}`, `self._tokens = itertools.count()`, `self._idle = asyncio.Event()` **already set**, and `self.draining = False`.

`register(*, ticket_id)` takes the next token, stores an `ActiveRun` with `time.monotonic()`, clears `_idle`, and returns the token. `deregister(token)` pops with a default of `None` (idempotent, and never frees another run's) and sets `_idle` when the map empties. `active` is a property returning `len(self._active)`. `snapshot()` returns `list(self._active.values())`.

`drain(*, timeout: float) -> bool` sets `self.draining = True` **first** — refusing new work is the first half of the contract, and it must happen even on the fast path. If nothing is active, return `True` immediately without logging a start event. Otherwise log `shutdown.drain_started` with the active count, `await asyncio.wait_for(self._idle.wait(), timeout=timeout)`, log `shutdown.drain_complete`, return `True`; on `except TimeoutError` log `shutdown.drain_timeout` with the active count and the in-flight `ticket_id`s and return `False`. Catch the builtin `TimeoutError` (3.11+ alias), not `asyncio.TimeoutError`.

Logging: `logger = logging.getLogger("relay.runs")`, short dotted event names as the message, all context in `extra={"ctx": {...}}`, never interpolated. Security constraint (ASVS V7): `ctx` passes straight through `JsonFormatter`, so carry `ticket_id`s and counts only — never ticket bodies, customer emails, or keys.

Three divergences from the `ratelimit.py` analog that each need a comment naming the reason:
1. This is a **class instantiated per app startup and stored on `app.state`**, not module-level globals. An `asyncio.Event` binds to the loop it is first awaited on; a module-level instance would outlive a `TestClient`'s loop and raise `RuntimeError: ... bound to a different event loop`.
2. **No TTL.** `reserve_run()` needs one because it is called in the handler and released in the generator. The registry registers *inside* the generator body, so register and deregister are exactly balanced — state this or a future reader will "fix" it by adding a TTL.
3. Because state is per-app, this module needs **no `reset_limits()` equivalent** and must not be added to `conftest.py`'s autouse reset.

Keyword-only for `register` and `drain` per the local convention. Full type hints, modern `X | None` union syntax.

Do not import anything from `main.py` — the registry must be testable without a `TestClient`.

  <action>
Rewrite `src/relay/db.py` around two new classes plus the changed `connect`/`init_db`, following RESEARCH.md § Pattern 1 verbatim.

`Result` — a materialised query result with `__slots__` of `_i`, `_rows`, `description`, `lastrowid`, `rowcount`. Implements `fetchone`, `fetchall`, `fetchmany(size=1)`, and `__iter__`. It holds a list of `sqlite3.Row` captured at construction; it never holds a cursor. Its docstring must name the failure it prevents: returning the live cursor lets the caller step it after the lock is released, and the observed damage is rows with `customer_email=None` and `status=''` — **not** `sqlite3.OperationalError: database is locked`. That is the whole reason this class exists.

`Database` — sole owner of the process's `sqlite3.Connection`. Store the connection in `self._conn` (private; nothing outside the class may reach it) and a `threading.RLock` in `self._lock`. `RLock`, not `Lock`: `transaction()` calls `execute()` re-entrantly. Provide a private `_run(method, *args)` that acquires the lock, calls the named connection method, and returns `Result(cur.fetchall(), cur.lastrowid, cur.rowcount, cur.description)` **before releasing the lock**. Build `execute(sql, params=())`, `executemany(sql, seq)`, and `executescript(script)` on top of `_run`. `commit()`, `rollback()`, and `close()` each take the lock around the corresponding connection call.

`Database.transaction()` — a `@contextlib.contextmanager` that holds `self._lock` for the whole block, `yield self`, then `self._conn.commit()` on clean exit. On exit, `except BaseException: self._conn.rollback(); raise`. It must be `BaseException`, not `Exception` — a bare `except Exception` lets a `CancelledError` escape with the transaction still open. The docstring states why: `commit()` is connection-scoped, so an INSERT+UPDATE pair that drops the lock between statements can be committed halfway through by another request, and its own rollback then undoes nothing.

`connect(db_path: str | Path) -> Database` — open with `check_same_thread=False` as today, set `row_factory = sqlite3.Row`, then issue three pragmas as separate `execute` calls in the existing one-pragma-per-line style: `PRAGMA journal_mode = WAL`, `PRAGMA busy_timeout = 5000`, `PRAGMA foreign_keys = ON`. Comment the WAL line with the fact that it is a silent no-op on `:memory:` (SQLite returns `memory` and raises nothing) and point at `tests/test_db.py`, which asserts that. Comment the `busy_timeout` line with the fact that Python's `sqlite3` already derives 5000 ms from `connect(timeout=5.0)` — the pragma is documentation that survives a future `timeout=` change, not the load-bearing fix PITFALLS.md implies. Return `Database(conn)`.

Do **not** use `sqlite3.Connection.autocommit` — it is 3.12+ and `pyproject.toml` declares `requires-python = ">=3.11"`. `transaction()` relies on legacy implicit-`BEGIN` transaction control.

`init_db(conn: Database) -> None` — body unchanged in behaviour; only the type hint changes. Keep the parameter name `conn`: every call site passes positionally and two of those call sites (`mcp_server.py`, `evals.py`) are protected by D-03.

Append the D-10 index to the end of the `SCHEMA` string, in the same blank-line-separated style as the `CREATE TABLE` statements: `CREATE INDEX IF NOT EXISTS idx_runs_created_at ON runs(created_at);`. `init_db` already runs `executescript(SCHEMA)` on every startup, so it self-applies with no migration. Justify it in a comment: `spent_today()` scans the whole `runs` table on the event loop for every gated request.

Extend the module docstring in the CONVENTIONS.md "docstring explains *why*" voice — this module now owns connection ownership and transaction boundaries, which is the point of the change and must be stated where the class lives.

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Tampering | `Database.transaction()` / `commit()` | mitigate | `commit()` is connection-scoped; hold the `RLock` across the whole statement group so one request cannot commit another's partial transaction. Proven by `test_a_failed_write_does_not_leave_a_partial_row_when_another_thread_commits` |
| T-02-02 | Information Disclosure | `Database.execute()` return value | mitigate | Materialise rows inside the lock (`Result`). Returning a live cursor lets a concurrent statement interleave with an in-flight read; the measured symptom was null/empty columns, and a subtler variant returns another request's rows |
| T-02-03 | Tampering | SQL statement construction | accept | Unchanged from today — every statement is parameterised and the wrapper passes `params` through untouched, adding no string formatting. Grep gate: no f-string or `%`-format reaches `execute` |
| T-02-04 | Denial of Service | `RLock` contention under `to_thread` | accept | Default executor is 5-12 workers; every critical section is a single materialised statement measured in microseconds. WAL + `busy_timeout=5000` handle SQLite-level contention in C |
| T-02-SC | Tampering | dependency installs | accept | This phase installs **no** packages (RESEARCH.md § Package Legitimacy Audit: not applicable). No `pip install` task exists in this plan; the gate is that `pyproject.toml` is not in `files_modified` |

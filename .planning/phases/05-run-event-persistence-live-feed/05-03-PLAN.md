<objective>
Wire the recorder end-to-end so a real run durably persists its full event sequence and mirrors a redacted projection to the broker — without touching evals.py or mcp_server.py. `run_ticket` gains an optional `recorder`; the write-tool offload uses `execute_and_record` so the event row shares the tool's transaction (D-04); `event_stream` mints the `run_uid`, builds the `RunRecorder`, publishes `project(event)` strictly after each event surfaces (post-commit, D-06), and passes `run_uid` to `record_run`; `lifespan` constructs `app.state.broker`.

Purpose: This is where persistence and the live mirror become real for a run, and where the load-bearing end-to-end redaction leak test runs. The `/events` HTTP route is Plan 04 — this plan proves the data path via the broker directly.

Output: Changed `agent.py`, `main.py`; `conftest.py` capture helper; integration tests for full-sequence persistence, publish-after-commit, and the mutation-checked redaction leak.
</objective>

<objective>
Lay the durable-storage foundation for run-event persistence: the `run_events` table, the `runs.run_uid` join column (added by a guarded, idempotent migration — the one genuinely new DB idiom in this repo), the `record_run` change that stamps `run_uid` on the summary row, and the three defaulted `config.py` settings the broker/`/events` layers will read later.

Purpose: Every later plan (recorder, broker, `/events`) depends on this schema and these settings existing. Getting the `ALTER TABLE` guard right here is what makes the column actually appear on the live Fly volume (D-13) instead of being a silent no-op.
